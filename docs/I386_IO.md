# i386 I/O implementation

## Console

The runtime writes 16-bit VGA text cells at physical address `0xB8000`. It tracks a row and column, updates the VGA hardware cursor through ports `0x3D4` and `0x3D5`, wraps at 80 columns, and scrolls after row 24.

`putl` prints every supplied `str`, `int`, and `bool` value without a newline. `putsc` prints the same values and then one newline. Integer conversion is handled by the i386 runtime. All output is mirrored to QEMU debug port `0xE9`.

The VGA attribute byte is configurable for future output:

```baf
Console.SetTextColor(10)
Console.SetTextBackgroundColor(1)
putsc("Light green text on blue")
```

Colors are VGA values `0` through `15`. Values outside that range are masked to the low four bits. Changing a color affects newly written characters and newly cleared cells; it does not repaint existing text.

## Keyboard

`inpt` polls the PS/2 controller:

- status port: `0x64`
- data port: `0x60`
- scan-code set: translated set 1

The current driver supports US-QWERTY printable keys, left/right Shift, Backspace, and Enter. It echoes characters and returns a borrowed BAF string with a maximum of 255 bytes.

BackAndForth 0.6.0 assigns a separate static 256-byte buffer to every lexical `inpt()` call site. Repeating the same call site overwrites its previous value, but a second `inpt()` elsewhere no longer corrupts the first value. This fixes filename/content aliasing in simple editors and shells.

## Power

`Power.Shutdown()` writes common emulator ACPI shutdown values, including QEMU port `0x604`. `Power.Reboot()` sends command `0xFE` to the PS/2 controller command port.

## Why polling first

Polling avoids requiring an IDT, PIC remapping, interrupt handlers, and concurrency before the language can demonstrate interactive input. Interrupt-driven input is planned for the next kernel architecture milestone.
